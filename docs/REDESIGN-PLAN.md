# REDESIGN PLAN — ปรับ UI ตามภาพอ้างอิง (`UI.md` = SVG 1280×720)

Status: อนุมัติทิศทางแล้ว (คำตอบผู้ใช้ 3 ข้อ ดูข้อ 7) | ยังไม่แก้โค้ด — รอบนี้วางแผน, รอบหน้าออกแบบ (R1) แล้วสร้าง

## 1. ภาพอ้างอิงมีอะไร (อ่านจากไฟล์ SVG โดยตรง)
- **เฟรม 1280×720 โหมดมืด** พื้น `#0A090D`, การ์ด `#1F1B26` รัศมี 12px ไม่มีเส้นขอบเด่น, เงาฟุ้งบางๆ, ลำแสงเบลอมุมขวาบน/ล่างซ้ายเป็นพื้นหลัง
- **Sidebar แถบไอคอน** กว้าง 84px แนวตั้ง 4 ไอคอน (stroke 1.5, ม่วง `#9A4DFF` เมื่อ active + จุดสถานะ), ไม่มีข้อความ
- **หัวหน้า** "Visão Geral" (= ภาพรวม) มุมซ้ายบน ขนาดกลาง ไม่ใหญ่
- **แถว 1: การ์ด KPI 4 ใบเท่ากัน** (271×146) แต่ละใบ = ชื่อ, ตัวเลขใหญ่, ไอคอนมุมขวา, ตัวชี้วัดเปลี่ยนแปลง ▲15% (เขียว `#15FF9E`) / ▼ (แดง `#FF1430`) "vs. ปีก่อน"
- **แถว 2–3 (กริดไม่สมมาตร):** กราฟแท่งตามเวลา (567×212, ม่วง), กราฟพื้นที่ซ้อน 2 ชุด (ม่วง/ฟ้า), กราฟแท่งนอนสูง (271×448, ม่วงไล่ความเข้ม), โดนัทมีตัวเลขกลาง (น้ำเงินเข้ม `#141BAF`), กราฟกรวย/funnel (ฟ้า `#10B1F0`)
- ข้อความในภาพเป็นโปรตุเกส/ตัวเลข R$ (ข้อมูลตัวอย่างของแดชบอร์ดขาย) — **ใช้เป็นโครงสร้าง ไม่ใช่เนื้อหา**
- Typeface: sans-serif แบบ Segoe/Inter-like หนา 600 สำหรับตัวเลข

## 2. ทิศทางสี (ผู้ใช้ตัดสินแล้ว)
ผู้ใช้สั่ง: **layout ตามภาพ แต่ใช้สีน้ำเงินเข้มกับฟ้าอ่อนเท่านั้น (ไม่ใช้ม่วง)** — ซึ่งตรงกับกฎ "ไม่ม่วง/นีออน" ของ design skill พอดี
ร่าง token (ยังไม่ final — R1 จะวัด contrast จริงก่อนล็อกค่า):
| token | โหมดมืด (หลักตามภาพ) | หมายเหตุ |
|---|---|---|
| `--bg` | `#060B16` น้ำเงินเกือบดำ | แทน `#0A090D` ของภาพ, ไม่ใช้ `#000` |
| `--surface` | `#0F1A30` | แทนการ์ด `#1F1B26` |
| `--surface-2` | `#16233F` | พื้นรอง/hover |
| `--blue` (น้ำเงินเข้ม) | `#2F5BE0` | ชุดข้อมูลหลักในกราฟ, ปุ่มหลัก (ต้อง ≥3:1 บนการ์ด) |
| `--sky` (ฟ้าอ่อน) | `#8FD3FF` | ข้อความเน้น/ไอคอน active/ชุดข้อมูลที่ 2/ตัวเลขสำคัญ |
| `--up` / `--down` | เขียว/แดงเดิมของเรา | **สื่อความหมายเท่านั้น (▲▼ +/−)** — ผู้ใช้ไม่ได้พูดถึง ถ้าไม่ต้องการ ให้บอก จะใช้ฟ้า/น้ำเงินแยกด้วยรูปทรง (▲▼) แทน |
โหมดสว่าง: เก็บไว้ตามข้อกำหนดเดิมของผู้ใช้ (สลับได้) ใช้คู่น้ำเงินเข้ม/ฟ้าอ่อนเดียวกัน บนพื้นขาวอมฟ้า — ผมออกแบบเอง (ภาพไม่มี)
ไม่ใส่ glow/neon ที่ปุ่มหรือกราฟ (ภาพก็ไม่มี), ลำแสงเบลอพื้นหลังเป็น pseudo-element คงที่ (ไม่กระทบประสิทธิภาพ)

| KPI 2 | รายรับเดือนนี้ ▲% vs เดือนก่อน | tx |
| KPI 3 | รายจ่ายเดือนนี้ ▲▼% vs เดือนก่อน | tx |

## 6. ความเสี่ยง/ข้อสังเกต
- กราฟพื้นที่ "ยอดสะสม" จาก tx ไม่ตรงกับ fm.balance เสมอ (ยอดเงินตั้งค่าเองได้) ⇒ เสนอวาด "การเปลี่ยนแปลงสุทธิสะสม" และติดป้ายให้ชัด ไม่ใช่ยอดคงเหลือ
- Chart.js ไม่มี funnel ในตัว (ต้องวาดเองด้วยแท่งนอนหรือ SVG) ⇒ เสนอไม่ทำ funnel
- พื้นดำม่วง + ม่วงนีออน เสี่ยง contrast ของข้อความรองบนการ์ด `#1F1B26` — ต้องวัดจริง
- ภาพไม่มีโหมดสว่าง ต้องออกแบบเพิ่ม (ถ้าเก็บโหมดสว่าง)
- ทุกอย่างบน Vercel/ซิงก์ที่ทำไว้ต้องไม่พัง — R7 ครอบคลุม

## 7. การตัดสินใจของผู้ใช้ (บันทึกแล้ว)
1. สี: layout ตามภาพ ใช้ **น้ำเงินเข้ม + ฟ้าอ่อน เท่านั้น** (ไม่ม่วง)
2. **เพิ่มหมวดหมู่รายจ่าย** (กราฟแท่งนอน + โดนัทมีข้อมูลจริง)
3. **หลายหน้า**: ภาพรวม / รายการ / กิจวัตร (hash routing, แถบไอคอนซ้าย → bottom tab บนมือถือ)

## 8. ยังต้องยืนยันตอนเริ่ม R1 (ผมถามครั้งเดียวพร้อม mockup)
- เขียว/แดงสำหรับ ▲▼ +/− ยังใช้ได้ไหม (ข้อ 2 ตาราง token)
- รายชื่อหมวดหมู่เริ่มต้น (เสนอ: อาหาร, เดินทาง, ที่พัก/บิล, ช้อปปิ้ง, สุขภาพ, บันเทิง, อื่นๆ — แก้ได้) และหมวดของรายรับ (เสนอ: เงินเดือน, รายได้เสริม, อื่นๆ)
- กราฟ funnel ในภาพ: เสนอเปลี่ยนเป็น "รายการล่าสุด" (เพราะข้อมูลของเราไม่มีลำดับขั้น)

### 9.1 หน้าและการนำทาง (hash routing, ไม่มี build)
| route | หน้า | เนื้อหา |
|---|---|---|
| `#/` | ภาพรวม | KPI 4 + กราฟ (กริดข้อ 9.3) |
| `#/tx` | รายการ | รายการรับ-จ่ายทั้งหมด (ใหม่→เก่า), ตัวกรอง ทั้งหมด/รายรับ/รายจ่าย, แสดงหมวด, ปุ่มลบ (ย้อนยอด), ปุ่ม "บวกเพิ่ม" |
| `#/tasks` | กิจวัตร | แผงงานประจำวัน (tasks.js เดิม) ขนาดเต็มหน้า |
- เดสก์ท็อป ≥1024: rail ซ้ายกว้าง 84px ไอคอน 3 ตัว (ภาพรวม/รายการ/กิจวัตร) + ปุ่มล่างสุดของ rail = สลับธีม; ไอคอน active = สี `--sky` + จุดสถานะเล็กข้างๆ ตามภาพ; แต่ละไอคอนมี `aria-label` + tooltip ข้อความ
- มือถือ <768: rail → bottom tab bar ติดล่าง 3 แท็บ (ไอคอน + ข้อความสั้น) เว้นระยะ safe-area, เนื้อหามี padding-bottom ไม่ให้ถูกบัง; แท็บเล็ต 768–1023: ใช้ rail แคบ
- Header ของหน้า: ชื่อหน้า (h1 หนึ่งตัว/หน้า, น้ำหนัก 600, ไม่ใหญ่) ซ้าย; ขวา: ปุ่ม **"อ่านสลิป"** (primary, เปิด drawer), ส่วนล็อกอิน/ซิงก์ของ cloud.js (ย้ายที่อยู่ได้ แต่ไม่แก้ตรรกะ), ปุ่มธีมบนมือถือ (บนเดสก์ท็อปอยู่ใน rail)
- Router: เปลี่ยนหน้าด้วยการซ่อน/แสดง `<section data-page>` (ไม่ทำลาย DOM โมดูล), อัปเดต `aria-current="page"`, ย้าย focus ไปที่ h1 ของหน้า, อัปเดต `document.title`, หน้า 404 → ภาพรวม, ปุ่มย้อนกลับของเบราว์เซอร์ใช้ได้; เปลี่ยนหน้า fade+translateY 8px ≤200ms (เคารพ reduced-motion)
- **Slip drawer**: `<dialog>` เลื่อนจากขวา (เดสก์ท็อป กว้าง 440px) / จากล่างเต็มกว้าง (มือถือ), `showModal()`, Esc ปิด, ปิดแล้ว focus กลับปุ่มเปิด; โหลด slip.js เดิมเข้า `#slip-root` ข้างใน (ตรรกะไม่เปลี่ยน นอกจาก R5 เพิ่มเลือกหมวด)
- **Adjust dialog** (ปรับยอด): `<dialog>` กลางจอ ใช้ฟอร์มตั้งยอดใหม่/บวกเพิ่มเดิมของ balance.js; เปิดจากปุ่ม "ปรับยอด" ในการ์ดยอดเงิน และจากปุ่ม "บวกเพิ่ม" ในหน้ารายการ

- การ์ด: `--surface`, รัศมี 12px, **ไม่มีขอบ** (ใช้ความต่างของพื้น) + เงาฟุ้งบางย้อมสีพื้น; ในโหมดสว่างใช้ขอบ 1px `--line`; ห้าม glow/neon/gradient ข้อความ; พื้นหลังมีลำแสงเบลอ 2 ก้อนสี `--surface` (ตามภาพ) ด้วย pseudo-element `position:fixed; pointer-events:none` (ไม่ใช้ filter ที่ scroll container)
- ฟอนต์เดิม (Outfit + Noto Sans Thai + Geist Mono ตัวเลข); ตัวเลข KPI 2rem/600 Geist Mono; ป้ายชื่อการ์ด 0.875rem `--muted`
- สีกราฟ: ชุดหลัก `--blue`, ชุดที่สอง `--sky`; หมวดหมู่ = ไล่เฉดน้ำเงิน→ฟ้า (≤5 เฉด + "อื่นๆ/ไม่ระบุ" เทาน้ำเงิน) แยกด้วยป้ายชื่อ+ตัวเลขเสมอ (ห้ามพึ่งสีอย่างเดียว); ▲ เขียว/▼ แดง ต้องมีสัญลักษณ์และตัวเลข %

### 9.3 หน้าภาพรวม (กริด 4 คอลัมน์ ตามภาพ; มือถือ → คอลัมน์เดียว)
```
[KPI ยอดเงิน] [KPI รายรับ ▲%] [KPI รายจ่าย ▲▼%] [KPI งานวันนี้ x/y]
[กราฟแท่ง รายรับ vs รายจ่าย 7/30 วัน (2 คอล)] [แท่งนอน รายจ่ายตามหมวด (1 คอล × 2 แถว)] [โดนัท รายรับตามหมวด]
[กราฟพื้นที่ การเปลี่ยนแปลงสุทธิสะสม (2 คอล)]                                         [รายการล่าสุด 5 รายการ]
```
- KPI ยอดเงิน: ตัวเลขใหญ่ + ปุ่มไอคอน "ปรับยอด"; KPI รายรับ/รายจ่าย = ยอดรวมเดือนปฏิทินปัจจุบัน + ▲▼ % เทียบเดือนก่อน (ไม่มีข้อมูลเดือนก่อน → "—" ไม่แสดง %); KPI งาน = x/y วันนี้ + แถบ progress
- ทุกกราฟมี: หัวข้อ, empty state ไทย, error state (Chart.js โหลดไม่ได้), ตารางซ่อนสำหรับ screen reader, สีจาก token, อัปเดตเมื่อ `tx:changed`/`theme:changed`
- กราฟแท่ง: สลับ 7 วัน/30 วัน (segmented control เข้าถึงได้); กราฟพื้นที่ = สะสม (รายรับ−รายจ่าย) ติดป้าย "การเปลี่ยนแปลงสุทธิ" ไม่ใช่ยอดคงเหลือ; แท่งนอน = รายจ่ายเดือนนี้ตามหมวด เรียงมาก→น้อย ≤7 แท่ง; โดนัท = รายรับเดือนนี้ตามหมวด + ยอดรวมตรงกลาง; "รายการล่าสุด" = 5 รายการ (ไอคอน +/−, หมวด, จำนวน, เวลา) ลิงก์ "ดูทั้งหมด" → `#/tx`

### 9.4 ข้อมูล
- tx ใหม่ = `{id,type,amount,ts,source,category}` โดย `category` เป็น key จาก `FM.cats` หรือ `null`; tx เดิมไม่มี category ต้องไม่พัง (แสดง "ไม่ระบุ")
- Slip drawer: หลังอ่านยอด มี select "หมวดหมู่" (ตาม type ที่กดยืนยัน — ผู้ใช้เลือกหมวดก่อนกดรายรับ/รายจ่าย; ค่าเริ่มต้น "อื่นๆ"); ฟอร์ม "บวกเพิ่ม" (income) มี select หมวดรายรับ
- cloud.js: ซิงก์ฟิลด์ `category` (validate ด้วย `FM.cats.normalize`; คอลัมน์ฝั่งฐานข้อมูลพร้อมแล้ว, อนุญาต null)
