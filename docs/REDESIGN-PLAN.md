# REDESIGN PLAN — ปรับ UI ตามภาพอ้างอิง (`UI.md` = SVG 1280×720)

Status: อนุมัติทิศทางแล้ว (คำตอบผู้ใช้ 3 ข้อ ดูข้อ 7) | ยังไม่แก้โค้ด — รอบนี้วางแผน, รอบหน้าออกแบบ (R1) แล้วสร้าง

## 1. ภาพอ้างอิงมีอะไร (อ่านจากไฟล์ SVG โดยตรง)
- **เฟรม 1280×720 โหมดมืด** พื้น `#0A090D`, การ์ด `#1F1B26` รัศมี 12px ไม่มีเส้นขอบเด่น, เงาฟุ้งบางๆ, ลำแสงเบลอมุมขวาบน/ล่างซ้ายเป็นพื้นหลัง
- **Sidebar แถบไอคอน** กว้าง 84px แนวตั้ง 4 ไอคอน (stroke 1.5, ม่วง `#9A4DFF` เมื่อ active + จุดสถานะ), ไม่มีข้อความ
- **หัวหน้า** "Visão Geral" (= ภาพรวม) มุมซ้ายบน ขนาดกลาง ไม่ใหญ่
- **แถว 1: การ์ด KPI 4 ใบเท่ากัน** (271×146) แต่ละใบ = ชื่อ, ตัวเลขใหญ่, ไอคอนมุมขวา, ตัวชี้วัดเปลี่ยนแปลง ▲15% (เขียว `#15FF9E`) / ▼ (แดง `#FF1430`) "vs. ปีก่อน"
- **แถว 2–3 (กริดไม่สมมาตร):** กราฟแท่งตามเวลา (567×212, ม่วง), กราฟพื้นที่ซ้อน 2 ชุด (ม่วง/ฟ้า), กราฟแท่งนอนสูง (271×448, ม่วงไล่ความเข้ม), โดนัทมีตัวเลขกลาง (น้ำเงินเข้ม `#141BAF`), กราฟกรวย/funnel (ฟ้า `#10B1F0`)
- ข้อความในภาพเป็นโปรตุเกส/ตัวเลข R$ (ข้อมูลตัวอย่างของแดชบอร์ดขาย) — **ใช้เป็นโครงสร้าง ไม่ใช่เนื้อหา**
- Typeface: sans-serif แบบ Segoe/Inter-like หนา 600 สำหรับตัวเลข

## 2. ทิศทางสี (ผู้ใช้ตัดสินแล้ว)
ผู้ใช้สั่ง: **layout ตามภาพ แต่ใช้สีน้ำเงินเข้มกับฟ้าอ่อนเท่านั้น (ไม่ใช้ม่วง)** — ซึ่งตรงกับกฎ "ไม่ม่วง/นีออน" ของ design skill พอดี
ร่าง token (ยังไม่ final — R1 จะวัด contrast จริงก่อนล็อกค่า):
| token | โหมดมืด (หลักตามภาพ) | หมายเหตุ |
|---|---|---|
| `--bg` | `#060B16` น้ำเงินเกือบดำ | แทน `#0A090D` ของภาพ, ไม่ใช้ `#000` |
| `--surface` | `#0F1A30` | แทนการ์ด `#1F1B26` |
| `--surface-2` | `#16233F` | พื้นรอง/hover |
| `--blue` (น้ำเงินเข้ม) | `#2F5BE0` | ชุดข้อมูลหลักในกราฟ, ปุ่มหลัก (ต้อง ≥3:1 บนการ์ด) |
| `--sky` (ฟ้าอ่อน) | `#8FD3FF` | ข้อความเน้น/ไอคอน active/ชุดข้อมูลที่ 2/ตัวเลขสำคัญ |
| `--up` / `--down` | เขียว/แดงเดิมของเรา | **สื่อความหมายเท่านั้น (▲▼ +/−)** — ผู้ใช้ไม่ได้พูดถึง ถ้าไม่ต้องการ ให้บอก จะใช้ฟ้า/น้ำเงินแยกด้วยรูปทรง (▲▼) แทน |
โหมดสว่าง: เก็บไว้ตามข้อกำหนดเดิมของผู้ใช้ (สลับได้) ใช้คู่น้ำเงินเข้ม/ฟ้าอ่อนเดียวกัน บนพื้นขาวอมฟ้า — ผมออกแบบเอง (ภาพไม่มี)
ไม่ใส่ glow/neon ที่ปุ่มหรือกราฟ (ภาพก็ไม่มี), ลำแสงเบลอพื้นหลังเป็น pseudo-element คงที่ (ไม่กระทบประสิทธิภาพ)

## 3. แปลงเนื้อหาขาย → เนื้อหาการเงินของเรา
| ช่องในภาพ | ของเรา | ข้อมูลจาก |
|---|---|---|
| KPI 1 | ยอดเงินปัจจุบัน (มีปุ่มตั้งยอด/บวกเพิ่มในการ์ดหรือ popover) | fm.balance |
| KPI 2 | รายรับเดือนนี้ ▲% vs เดือนก่อน | tx |
| KPI 3 | รายจ่ายเดือนนี้ ▲▼% vs เดือนก่อน | tx |
| KPI 4 | งานวันนี้ x/y (หรืออัตราทำครบ 7 วัน) | tasks |
| กราฟแท่งกว้าง | รายรับ vs รายจ่าย 7 วัน / 30 วัน (สลับช่วง) | tx |
| กราฟพื้นที่ | ยอดเงินสะสมตามเวลา (รายรับ − รายจ่าย สะสม) | tx (ดูข้อ 2 ด้านล่าง) |
| แท่งนอนสูง | รายจ่ายตามหมวดหมู่ (อันดับ) | **ต้องมีหมวดหมู่** |
| โดนัท | สัดส่วนรายรับ/รายจ่าย หรือตามหมวด/แหล่งที่มา (สลิป vs กรอกเอง) | tx |
| funnel | ยังไม่มีข้อมูลที่เหมาะ — เสนอเปลี่ยนเป็น "รายการล่าสุด" หรือ "สลิปที่อ่าน → ยืนยัน" | — |
ฟีเจอร์เดิม (อ่านสลิป, งานประจำวัน, ประวัติ+ลบ, ล็อกอิน/ซิงก์) ต้องมีที่อยู่ในเลย์เอาต์ใหม่ — เสนอ: **อ่านสลิป = ปุ่มหลักในส่วนหัวเปิด drawer/โมดัล**, **งานประจำวัน = หน้า/แผงในแถบข้างหรือหน้า "กิจวัตร"**, **ประวัติ = หน้า "รายการ"**

## 4. โครงหน้า (เสนอ)
```
┌ rail ┬ ภาพรวม ───────────────────── [อ่านสลิป] [ซิงก์/ล็อกอิน] [ธีม] ┐
│ ◧    │ [ยอดเงิน] [รายรับ] [รายจ่าย] [งานวันนี้]                    │
│ ▤    │ [กราฟแท่ง 7/30 วัน  ][แท่งนอน  ][โดนัท]                      │
│ ∿    │ [กราฟพื้นที่ สะสม   ][หมวด    ][รายการล่าสุด]                │
│ ☑    │                                                              │
└──────┴──────────────────────────────────────────────────────────────┘
```
มือถือ (<768): rail เปลี่ยนเป็น bottom tab bar 4 ไอคอน (มีป้ายข้อความ), KPI เป็นสไลด์แนวนอน/2 คอลัมน์, กราฟเรียงคอลัมน์เดียว

## 6. ความเสี่ยง/ข้อสังเกต
- กราฟพื้นที่ "ยอดสะสม" จาก tx ไม่ตรงกับ fm.balance เสมอ (ยอดเงินตั้งค่าเองได้) ⇒ เสนอวาด "การเปลี่ยนแปลงสุทธิสะสม" และติดป้ายให้ชัด ไม่ใช่ยอดคงเหลือ
- Chart.js ไม่มี funnel ในตัว (ต้องวาดเองด้วยแท่งนอนหรือ SVG) ⇒ เสนอไม่ทำ funnel
- พื้นดำม่วง + ม่วงนีออน เสี่ยง contrast ของข้อความรองบนการ์ด `#1F1B26` — ต้องวัดจริง
- ภาพไม่มีโหมดสว่าง ต้องออกแบบเพิ่ม (ถ้าเก็บโหมดสว่าง)
- ทุกอย่างบน Vercel/ซิงก์ที่ทำไว้ต้องไม่พัง — R7 ครอบคลุม

## 7. การตัดสินใจของผู้ใช้ (บันทึกแล้ว)
1. สี: layout ตามภาพ ใช้ **น้ำเงินเข้ม + ฟ้าอ่อน เท่านั้น** (ไม่ม่วง)
2. **เพิ่มหมวดหมู่รายจ่าย** (กราฟแท่งนอน + โดนัทมีข้อมูลจริง)
3. **หลายหน้า**: ภาพรวม / รายการ / กิจวัตร (hash routing, แถบไอคอนซ้าย → bottom tab บนมือถือ)

## 8. ยังต้องยืนยันตอนเริ่ม R1 (ผมถามครั้งเดียวพร้อม mockup)
- เขียว/แดงสำหรับ ▲▼ +/− ยังใช้ได้ไหม (ข้อ 2 ตาราง token)
- รายชื่อหมวดหมู่เริ่มต้น (เสนอ: อาหาร, เดินทาง, ที่พัก/บิล, ช้อปปิ้ง, สุขภาพ, บันเทิง, อื่นๆ — แก้ได้) และหมวดของรายรับ (เสนอ: เงินเดือน, รายได้เสริม, อื่นๆ)
- กราฟ funnel ในภาพ: เสนอเปลี่ยนเป็น "รายการล่าสุด" (เพราะข้อมูลของเราไม่มีลำดับขั้น)
